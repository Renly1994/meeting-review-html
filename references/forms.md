# 各形式的写法

头部、金句、图、可信度、“对你 / 我的判断”、原文在所有形式里都照常；变的只是“讲述顺序”那一块换成什么。组件片段见 components.md 第 4 节。

## 切段信号

| 信号 | 通常意味着 |
|---|---|
| ≥60 秒长静音 | 茶歇、换场、转去饭局 |
| “休息十分钟”“下面请 X 分享”“走，吃饭去”“我问你几个问题” | 形式切换 |
| 时间窗里一人占 70% 以上、字数多 | 分享、路演 |
| 两人交替，一方多为短问句 | 访谈、一对一 |
| 三人以上平均分布，字数偏低，话题跳 | 散聊 |
| 嘈杂、多人同时说、“这个好吃”“干杯” | 饭局 |
| “这个谁来跟”“下周三前”“那就这么定了” | 工作会议 |

| 形式 | data-type | 区块内怎么排 | h2 写法 |
|---|---|---|---|
| 分享、路演、圆桌 | `分享` `路演` `圆桌` | 金句 + 结构图 + 讲述顺序 + 问答 | 谁：核心主张 |
| 访谈、一对一 | `访谈` | 金句 + qblock 一问一答 | 和谁聊：最想弄清的问题 |
| 散聊、茶谈 | `散聊` | topic 按话题切 | 聊得最有价值的那件事 |
| 饭局 | `饭局` | 同散聊，只留有内容的话题 | 同上 |
| 工作会议 | `工作会` | 按议题 + decisions 表 | 这次会定了什么 |
| 茶歇、合影 | `茶歇` | 一句话带过 | 可以跳过时直接写“可以跳过” |

切段注意：
- 主持人通常是轮数多、字数少、贯穿全场的那个编号。
- 多份转写的先后看文件头开始时间；现场时间 = 开始时间 + 时间戳。
- 一个人被拆成几个编号，或一个编号混了几个人（自我介绍环节最常见）：以内容为准，在 `who`/`gist` 里写清“发言人4 前段是 A、后段是 B”。
- 多份转写各自编号，转写一的“发言人4”≠转写二的“发言人4”，alias 按文件写（`b:发言人4=…`）。
- 只有一场长对谈时，可以按话题切成几块，每块写清时间段和主要发言人。

## 分享 / 路演 / 圆桌

- 讲述顺序按讲者先后，保留逻辑链，删口水话，5–10 条。
- 统领整场的框架图紧跟金句；只对应某一段的图放在那段附近。一场超过 4 张图先想能否合并。
- 问答：追问没得到回答的，`qa-note` 点出来——这往往是全场最值钱的信号。
- 需求或判断在讲述中被推翻/修正（“一开始以为……后来发现……”），单独画一张 eras 演进图，这是最容易被纪要漏掉、复盘最有用的东西。

## 访谈 / 一对一

- 按提问顺序，每个问题下写回答要点。值钱的是答得含糊、绕开，或答出了没被问到的东西。
- 读者本人是提问方时，“我的判断”可以评哪个问题问得好、哪里该追问。

## 散聊 / 茶谈 / 饭局

- 一个话题一张 topic，同一话题聊回来就合并，时间写两段。寒暄不建卡，`gist` 一句带过（“前 10 分钟在聊考研，可以跳过”）。
- 饭局更狠地删：只留行业八卦、真实数字、谁在做什么、谁能介绍给谁。人脉线索单独一条（“老王说可以介绍做连锁餐饮的朋友”）。数字一律 `存疑`。

## 工作会议

- 按议题切，每个议题写讨论要点和分歧，再放 decisions 表。只记**已经说定**的，没定的写“还没定”。这是记录，不是替读者安排。
- “对你”写决定对读者的影响；“我的判断”可以指出哪个决定有风险、哪个没定的事最要紧。

## 茶歇 / 合影

`gist` 直接说“大部分可以跳过，X 起有一段有用”，只写有用那段；完全没内容的只在流程条里画成 `brk`，不建区块。

## 读者本人是主讲人时

被追问、自己分享、和别人对谈都算（先从画像里的名字、自我介绍认出是哪个编号）。页面是在帮读者复盘自己的表现（分享版改用名字、第三人称）：
- h2 主语是“你”（分享版写名字）：“你被追问了 40 分钟：怎么接单、怎么定价”。
- 讲述顺序改为“你按这个顺序回答”，原话照录。
- “对你”写：哪些回答讲清楚了、对方追问最多的是什么（说明对方真正关心什么）、哪句话能直接拿去做内容。
- “我的判断”指出哪里含糊、漏了什么、下次怎么讲，标 `推论`。语气是复盘，不是打分。

## 转写质量差的段

照常做，但 `gist` 写明“这段转写质量差”，图题标“按上下文拼的”，数字一律 `存疑`。大段不通的句子不硬解读。
