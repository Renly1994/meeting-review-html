# 写给谁：读者画像与两种模式

“对你”是这个 skill 和普通纪要最大的区别，也是最容易写空的部分。它好不好，取决于你对读者知道多少。

## 先定模式

| | 个人版 `--audience self`（默认） | 分享版 `--audience share` |
|---|---|---|
| 读者 | 用户本人（到过现场或没去） | 一群人：团队、社群、没到场的同事 |
| 场内两栏 | 对你 / 我的判断 | 可借鉴 / 复盘者判断 |
| 总节 | 对你：对照表 + 可以试的事 + 只记三句 | 怎么用：按角色对照表 + 可以试的事 + 只记三句 |
| 依据 | 读者画像 | 读者群画像（大家大致是做什么的） |
| 原文 | 全部嵌入 | 默认去掉私聊、饭局段；必要时整页不放 |

用户说“发给大家 / 发群里 / 给团队看 / 做成分享稿”就用分享版；没说就是个人版。拿不准问一句。

## 个人版：读者画像

按顺序找，找到就用：

1. 本 skill 目录下的 `profile.md`（照 `profile.example.md` 填的）
2. 你的记忆系统里关于用户的条目
3. 输出目录里以前的复盘页（看用户上次处在什么阶段）
4. 工作目录里近期的方案、文档；对话里说过的话

都没有时，**开工前一次性问三个问题**，允许用户跳过：

> 为了写“对你”这部分，想先了解三件事（可以跳过）：
> 1. 你现在主要在做什么（身份 / 业务 / 项目）？
> 2. 最近在推进或卡住的一两件事？
> 3. 这场会你最想带走什么？

答完后问用户要不要存进 `profile.md`，下次不用再问。用户跳过：照常做，“对你”只写 1–2 条、写成“如果你在做 X，……”的条件句，交付时说明“没有你的背景，这部分是通用写法”。

画像里出现的名字也用来在转写里认出读者本人（自我介绍、被人称呼），认出后按 forms.md“读者本人是主讲人时”写。

### 好的“对你”

把讲者的话接到读者手上具体的事：
- 好：“苏博说的‘先找能核对结果的小切口’，就是你在谈的那家门店：先只做库存盘点，别一上来做全套。”
- 差：“这对你的业务很有启发，可以借鉴。”（空话，删掉）
- 没关联就少写，不硬套。2 条实在的胜过 3 条凑数的。

## 分享版

读者是一群人，所以不能假设“你”在做什么：

- **可借鉴**（场内 2–3 条）：写给“做 X 的人”，带上适用条件。“做 ToB 交付的：……；只做内容的可以跳过这条。”
- **复盘者判断**：评观点、方法和证据，不评人。不写“某某水平一般”“他在吹牛”，改成“这个数字没有给出口径 `存疑`”。
- **怎么用总节**：对照表第一列写角色（2–4 类，从读者群推，比如创业者 / 销售 / 内容运营 / 技术）；可以试的事写成谁都能拿去试的小实验。
- **隐私**（交付前逐条过）：
  - 原文：私聊、饭局、自我介绍里的联系方式段，用 `init --redact "a:起-止"` 去掉；整场都敏感就 `--no-raw`。
  - 正文：不写人脉线索（“谁能介绍谁”）、私下透露的收入和客户名、没公开的融资数字；需要时只写“某制造业客户”。
  - 讲者自述的成绩一律标“自述”或 `存疑`，避免二次传播成事实。
  - 交付时提醒用户：转发前再看一遍讲者是否同意公开。
- 写完用 check 跑一遍，分享版里残留“对你”“放到你身上”会被提醒。

## 两种都要的

- 证据三声音不混：讲者说的（时间戳）、复盘者推论（`推论`）、待查（`存疑`）。
- “可以试的事”是启发，不加勾选、不排日期、不叫待办。
