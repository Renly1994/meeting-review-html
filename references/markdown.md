# Markdown 归档稿

每次复盘默认同时输出 HTML 和 UTF-8 编码的 `.md`，文件同目录、同名、同版本。Markdown 面向个人知识库，保持独立可读、可全文检索。

## 内容与写法

- 从与 HTML 相同的场次内容生成，保留完整层的事实、数字、案例、因果、问答、必要原话、可信度、“对你 / 我的判断”、跨场联系和启发。两份措辞可适应载体，实质信息应一致。
- 开头简要记录会议名称、会议日期、地点（有则写）、主要参与者、来源文件和个人版/分享版。时间估算、讲者身份存疑、转写质量等说明照实保留；不知道的信息不补猜。
- 按真实场次顺序组织，标题写清讲者、主题和时间范围；讲述顺序用编号列表，问答保留提问者、回答者和未答上的问题。
- 时间戳保留为普通文字，如 `01:47:31–01:48:21`；多份转写标明对应来源，分清转写时间与现场时间。
- 现场说法、复盘者判断和待查信息继续分开，保留“推论”“存疑”“自述”等标签，不把讲者成绩转述成已验证事实。
- 使用标准 Markdown 标题、段落、列表、引用和必要的表格。适合逐条阅读的宽表可改成按主题组织的列表。
- 不使用 HTML 标签、网页样式、脚本、交互按钮、折叠区块、图片、Base64 或 Mermaid。页面里的导航、速览开关、抽屉操作说明等不写入归档稿。
- 每个知识点在 Markdown 中直接写清，不用“见上图”“点击查看”“详见 HTML”代替内容。附网页链接可以作为补充，不能成为理解正文的前提。
- 默认不附整份转写原文；保留精选原话、时间戳、来源文件名和必要上下文。用户明确要求完整原文时，再作为附录整理；分享版继续遵循原有删减范围。
- 个人版沿用“对你 / 我的判断”，分享版沿用“可借鉴 / 复盘者判断”。HTML 中已隐去的内容，在对应 Markdown 中同样隐去。

## 图转成文字

图里的标签、条件、方向和结果都要在文字中交代，单纯罗列图中词语会丢掉逻辑。

- 流程、循环：写成按顺序的步骤或 `输入 → 处理 → 输出`，反馈回哪一步要说明。
- 阶段、时间轴：按阶段列出现状、变化条件、做法和结果。
- 对比、分类：用小型 Markdown 表格或按对象分组的列表，保留比较维度和适用条件。
- 因果、追问：写明“因为……所以……”“如果……则……”或问题与回答的递进。
- 插画：对应观点已在正文讲清时，无需描述画面；若图中包含正文没有的信息，将其写进相关段落。

例如，“ERP 搜索差 → 员工不用 → 找不到库存 → 重新买 → 重复采购损失”应保留整条链，并说明讲者为何把技术问题解释成经营损耗，保留该段来源时间；不能缩成“AI 可以提升效率”。

## 参考结构

沿用原复盘的场次和内容安排，下面的结构按实际会议增减：

1. 一级标题：会议主题与日期；其后列来源与必要说明。
2. 核心收获：对应 HTML 开场的主张和精选原话。
3. 全场流程：场次、时间、形式、主讲人和阅读判断；轻量版可省。
4. 各场次：背景与主线、金句、框架的文字解释、讲述顺序、现场问答、可信度、对你与复盘判断。未出现的环节不硬凑。
5. 串起来看：跨场共同点、对比和仍无结论的分歧；轻量版可省。
6. 对你（分享版为“怎么用”）：现场说法的应用对照、可以试的事、如果只记三句。
7. 来源说明：来源文件、时间计算方式、必要的转写局限。

## 交付检查

1. `.html` 与 `.md` 都已实际生成，同名、同版本；Markdown 编码为 UTF-8。
2. 逐场对照完整版 HTML：没有遗漏实质信息、问答、判断和时间戳；图中的关系已转成文字。
3. 抽查数字与引语：讲者、口径、时间和证据标签在两份中一致；分享版删减范围一致。
4. 纯文本打开 Markdown，确认不依赖图片或网页控件也能理解全文，没有残留 HTML、脚本或占位符。
